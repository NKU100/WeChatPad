# WeChatPad 设计说明

状态：待用户审阅

## 目标

构建 LSPosed 模块 `io.github.nku100.wechatpad`，为微信提供平板登录入口，以便用户尝试在已有手机之外登录同一账号。模块只改变微信客户端的平板登录表现，不承诺微信服务器一定允许多个移动设备会话长期并存。

首批兼容目标为微信 8.0.40 和 8.0.79：8.0.40 是旧版基线，8.0.79 是当前版回归目标。后续模块版本增加微信新版适配时，必须继续验证所有已支持的旧版。

## 范围与边界

- 首版实现完成平板登录所需的最小 Hook，不复刻 WeChatTablet 的无关功能，也不依赖或捆绑第三方微信模块。
- 只有包名、版本构建身份、APK 签名和 Hook 解析结果均通过验证的微信构建，才列为正式支持版本。
- 未知、缺少特征或解析到多个候选的构建一律不安装 Hook，并记录可诊断原因。
- AVD 冒烟只验证模块注入、微信启动、登录入口和二维码登录页面，不执行真实登录或验证服务器会话。
- 构建和兼容检查可以在 CI 上自动运行。首版不启用每日计划任务，不要求付费 API，也不自动合并兼容更新。

## 兼容核心

`compat-core` 是纯 Kotlin/JVM 库，不依赖 Android、LSPosed 或微信类。它负责：

1. 校验微信构建身份及已登记的兼容目标。
2. 根据共享的 Hook 特征定义，对 DEX 方法事实进行候选匹配。
3. 校验方法结构、参数和返回类型，并要求每个 Hook 恰好命中一个候选。
4. 输出可序列化的结果：兼容、未支持、特征缺失、签名不匹配、候选不唯一或 APK 身份不符。

Android 模块运行时与桌面兼容检查器必须调用同一份 `compat-core` 代码和同一份 Hook 特征定义。平台侧只提供 APK/DEX 数据及运行时可 Hook 的方法句柄；候选选择与安全判定不得各自复制一套实现。选择 DEX 读取方式时，先验证同一事实提取实现能否同时在 Android 运行时和 CI 使用；若必须有平台适配器，适配器只负责读取数据，核心匹配规则仍保持共用。

## 运行时行为

微信进程启动后，模块识别包名与构建身份，取得 DEX 方法事实并调用兼容核心。仅当平板模式 Hook 和登录入口 Hook 都唯一解析、签名校验通过时，才同时安装 Hook；任一失败则不安装任何 Hook，避免半启用状态。

成功解析结果可以缓存。缓存身份至少包含微信构建身份和解析器规则版本；微信 APK 或解析器规则改变时必须失效并重新解析。缓存损坏或版本不明时重新解析，不能将缓存错误降级为宽松匹配。

## 兼容清单与证据

`compatibility/targets.json` 登记每个微信构建的包名、版本名、版本码、渠道/ABI、APK SHA-256、签名证书摘要、Hook 特征版本及验证状态。状态至少区分：

- `static-verified`：APK 来源、哈希、签名和共用解析器检查通过。
- `runtime-verified`：在 AVD 上确认模块注入并完成登录界面冒烟。

静态通过不等同于正式兼容。旧版条目在后续模块升级中保留；只有完整矩阵回归通过才能继续标为 `runtime-verified`。

## CI 与后续适配

### 构建 CI

推送、Pull Request 和手动触发构建模块，检查包名，并运行 `compat-core` 测试。暂不启用定时构建。

### 兼容检查

CI 对清单内 APK 校验 SHA-256、签名和包身份，然后调用与模块相同的解析器检查两处 Hook。每次适配都运行已支持构建矩阵，特别确认 8.0.40 与 8.0.79 均未回归。

后续启用新版发现时，CI 下载候选 APK 并执行相同检查。唯一解析通过时，可以生成包含目标身份和静态结果的待审 PR；解析失败时生成诊断报告，不猜测 Hook 目标，也不把该版本标为支持。运行时验证仍由 AVD 矩阵完成，PR 不自动合并。CI 不调用需要额外付费的 ChatGPT API。

## 验收

1. 共用兼容核心的测试覆盖：唯一命中、零命中、多重命中、方法签名不符、未知构建、错误 APK 身份和缓存失效。
2. 8.0.40 与 8.0.79 的 APK 均通过身份校验；桌面检查器与运行时使用同一组特征定义和匹配结果。
3. 两版 AVD 冒烟均证明模块注入、微信不崩溃、登录入口出现且可进入二维码登录页面。
4. 一次新增版本适配的回归流程证明既有版本仍可解析；若任一旧版不通过，该更新不得扩大正式支持清单。
5. CI 可从干净检出构建模块并运行兼容核心测试。

## 实施顺序

1. 建立共用兼容核心和 JVM 测试，再验证 DEX 事实提取在 Android 与桌面 CI 的可复用边界。
2. 获取并校验 8.0.40、8.0.79 APK，建立两版兼容清单与解析特征。
3. 实现最小运行时 Hook，完成两版 AVD 登录界面冒烟及旧版回归。
4. 增加推送、PR、手动触发的构建 CI。
5. 增加新版兼容检测和待审更新 PR；每日触发留待单独启用。

## 尚待实现阶段验证的技术点

- 可否用同一个 DEX 读取实现从已安装微信 APK 和 CI 下载 APK 中生成完全一致的方法事实。
- 微信 8.0.40 与 8.0.79 上两处 Hook 特征的精确方法形态及其稳定性。
- LSPosed 运行时加载目标方法句柄的具体接口，以及缓存 APK 指纹的成本。

这些事项通过两版 APK 的实现前探测确认；若影响共用核心接口，应先更新本说明，再实现 Hook。
